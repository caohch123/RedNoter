# Pi 中栏浏览器逐项验收（阶段二）

阶段二要确认的是：**日常能力都能在网页里点完，只有真正依赖终端的才丢给网页终端**。这份文档记录怎么验、验了什么、以及还没做到的。

## 请求去重

网页侧：所有发送入口（发送 / 插话 / 追加 / 生成初稿 / 左栏「生成笔记」）都过同一个 `fire()`，用 ref 挡住并发点击，同一个输入不会进两轮。

接口侧：`PiRequest` 以 `requestId` 为主键。同内容重复提交返回 `202 duplicate`，不同内容复用同一 `requestId` 返回 `409 REQUEST_ID_CONFLICT`。已在本机用 curl 验过（`acceptedAtSeq` 一致）。

## 验收过程中修掉的问题

浏览器回归抓出三个在 curl 层看不到的问题，都已修复：

1. **SSE 地址漏了 `/api`**：`request()` 会自动加前缀，但 `new EventSource()` 不会。前端订阅的 `/v1/creation/pi/…/events` 直接打到 Next 上，全部 404，中栏永远停在「Pi 正在处理…」。拆成 `base`（给 `request`）和 `direct = /api + base`（给 EventSource、`<a download>`、`fileUrl`）。
2. **工具卡片一闪就没**：`use-pi-session` 在 `message_end` 里清空 `tools`，而带工具调用的助手消息正好在那之后结束。改成只在 `agent_settled` 且刷新完消息后清空。
3. **终端反复重连**：`PiTerminal` 的 effect 依赖父组件每次渲染都新建的 `closed` 回调，导致「关闭 → 重连」循环，终端一直画不出东西，事件流还撞出 503。回调改走 ref，effect 只依赖 `terminalId`。

另外两处是为了能验收才加的：终端加了一份去控制符的文本镜像（canvas 读屏和 Playwright 都拿不到字），网关把「终端已关闭」从 503 改成透传运行器的状态码。

### 2026-11-19：气泡、排版与停止后的队列

截图里有两处「看着像坏了」的地方，都属展示层：

1. **提问气泡把注入的上下文一起显示了**：网关为了让模型拿到左栏设置，会把主题、事实、当前正文拼成一整段再发，会话记录里存的就是这段全文，于是气泡里出现了一大坨「【摘星上下文】」。改成气泡只显示 `【用户请求】` 之后用户自己写的那句，旁边加一个小标签「已带左栏设置」（悬停说明带了什么）。历史消息同样按这个规则收，刷新后不会又冒出来。
2. **回复里的格式是原字符**：助手消息一直按纯文本渲染，粗体标记、列表符号、引用符全都原样露出来。新增 `web/src/components/creation/pi/Markdown.tsx`，覆盖标题、有序/无序列表、引用、围栏代码、粗体/斜体/删除线/行内代码/链接，全部走 React 元素拼装，不拼 HTML 字符串；流式输出也走同一套，收尾时不会突然换样子。

验收这轮还顺带修了一个真问题：**停止后排队消息不清空**。用户先「插话」再「停止」，插话会留在队列里，而队列只在流式期间投递，于是 `isStreaming` 一直为真、会话永远显示在执行中，终端也接管不了。`stop()` 现在 abort 之后调 `clearQueue()` 并等一下 `waitForIdle()`（3 秒封顶），`releaseForTerminal()` 同样清队列。

## 成稿质量回归（2026-11-19）

流程验收只能说明「链路通」，说明不了「稿子对不对」。`npm run test:pi-quality`（`tools/e2e/pi-quality.mjs`）补的是后者：同一个账号下连开两篇草稿，用两组不同的数字各跑一遍「原创 → 局部改稿 → 应用 → 并发手改 → 定稿」。

- 第一组：`能放 13 寸电脑`、`有两个内袋`，人群「早八通勤族」，主题「轻量通勤托特包」。
- 第二组：`能放 15 寸电脑`、`有三个外层袋`，人群「周末短途出行」，主题「周末短途双肩包」。

两篇草稿放在同一账号下，是为了让「上一稿的事实漏进这一稿」这种串味能真的暴露出来。

**结果：72/72 通过**（两次完整跑，报告 `.creation-pi/quality/report.json`）。

| 指标 | 第一组 | 第二组 |
| --- | --- | --- |
| 指定事实命中（2 条） | 2/2 | 2/2 |
| 无依据陈述（价格/实测/质保等） | 0 | 0 |
| 无依据数字（带单位的数字找不到事实依据） | 0 | 0 |
| 修改范围外差异（只改开头时） | 0 处 | 0 处 |

「无依据数字」是「逐句核对」的自动入口：正文里凡是 `数字 + 单位`（寸/个/层/元/克/升/天/次/小时/cm/kg/ml…）的说法，都要能在事实、主题、品类里找到同样写法，否则列出来供人工复核。两组都没有漏网的编造数字。

关键断言：

1. **模型实际收到的输入**取自运行器事件日志 `.creation-pi/events/<draft>.jsonl` 里 `message_end`（role=user）的正文，不是我们以为发了什么。两条事实、人群、`草稿版本 N`、「用户确认的事实」逐项在场。
2. **换数字不串味**：第二组的提示与正文里都不出现 `13 寸`、`两个内袋`、`早八通勤族`。
3. **局部改稿**：说「只改开头」时，`patch.title` / `patch.tags` 均为 `undefined`，第二段起逐字相同（`tail` 逐字比较），`baseRevision` 等于草稿当前版本。
4. **版本交错**：等模型这一轮先 `star_note_snapshot`，再人工改稿保存，候选的 `baseRevision` 落在人工版本之前；应用返回 409，人工改动保留、候选仍在可对照。第一组改的是「两个内袋 → 三个内袋」，第二组是补一句使用感受。
5. **定稿**：`checks` 0 错 0 提醒，`finalizations` 成功。

跑这轮时修正的是**脚本**、暴露出来的是**行为**：

- 候选出现时模型往往还在收尾，紧接着发下一条会撞 `SESSION_BUSY`（409）。脚本改为先等 `state.busy === false`。
- 人工改动如果先于模型读稿，模型读到的就已经是新版本，根本构不成冲突。脚本改成等 `star_note_snapshot` 工具调用出现后再 PATCH。
- 让模型自己把「两个内袋」改成「三个内袋」时，它会拒绝执行并追问——因为事实栏写的是两个内袋。这是规则在起作用，不是缺陷；所以并发用例改成「人工改数字、模型只改最后一句」，冲突由版本触发，而不是靠模型违心改事实。

本轮还改了发送链路（`fire()` 先同步、失败给「重试」），改完重跑浏览器回归仍是 **15/15**。

## 已知差距

- 联网授权是 `tool_call` 钩子层，不是内核层：沙箱本机仍然能出网，真正的隔离要等每稿容器。
- 终端专属扩展靠 `PI_TERMINAL_EXTENSIONS` 显式挂载，不是自动发现。
- 分享、MCP、包安装、OAuth 登录仍只能在网页终端里做。
